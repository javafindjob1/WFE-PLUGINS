## 1. 「出伤」的完整链路

```
引擎原生伤害 (EVENT_UNIT_DAMAGED)
  └─ lib/eventBinder.lua  damaged 条件
       · GetEventDamage() 取原伤害，立刻 EXSetEventDamage(0) 清零
       · 0 秒计时器里转成 hskill.damage{ damageSrc=attack/WULI 或 skill/MOFA }
  └─ lib/skill.lua  hskill.damage(options)
       ① 跑 damaging.actions 伤害流水线（scripts/damaging.lua 定义）
       ② 护盾吸收 hbuff.xiaochuhudun
       ③ hunit.subCurLife 扣血
       ④ hevent.trigger(target, CONST_EVENT.beDamage, {...})   ← 出伤显示挂在这里
  └─ scripts/eventReaction.lua  hevent.reaction(beDamage)  ← 真正画数字
```

**只有一条入口**：所有伤害（普攻、技能、DOT、反伤…）都被 `EXSetEventDamage(0)` 拦截后重新走 `hskill.damage`，所以**任何一次掉血必然会出数字**。

> 小坑：`local isAttack = hjapi.IsEventAttackDamage() or true` —— `or true` 让它恒为真，
> 于是引擎原生伤害一律按“普攻 / 物理”处理，`[非攻击] → 技能伤害` 那条分支是死代码。
> 法术伤害只有技能里显式 `hskill.damage{ damageSrc = skill, damageType = MOFA }` 才会出现
> （例：`lua_tree/scripts/skills/...` 里大量这种调用），所以“法术数字模型”只在这类技能上出。

`beDamage` 携带的字段（`lib/skill.lua:896`）：

```lua
{ triggerUnit = 被打单位, sourceUnit = 来源单位,
  damage = 护盾吸收后的最终伤害,
  damageSrc, damageType,      -- DAMAGE_TYPE.WULI / MOFA / SHENSHENG
  isCritical,                 -- 是否暴击
  triggerSkill, shanghainame, damageSpeedType }
```

## 2. 两条渲染路线（核心）

`scripts/eventReaction.lua` 的 `beDamage` 反应：

```lua
if hplayer.isUser(hunit.getOwner(evtData.triggerUnit)) == true then
    -- A. 被打的是“玩家单位” → 文字
else
    -- B. 被打的是怪/BOSS → 数字模型
end
```

### A. 玩家单位：原生 TextTag 红字

```lua
local tag = htextTag.create2XY(
    hunit.x(u), hunit.y(u),
    "-" .. string.format("%.0f", evtData.damage),
    9, "e32a00", 1, 1, 50)
htextTag.setVelocity(tag, 0, 0.05)
```

| 参数 | 值 | 说明 |
|---|---|---|
| 文本 | `-1234` | `math.floor` 后取整，前面加负号 |
| 字号 | `9` | 实际字高 `9*0.023/10 = 0.0207`（世界单位） |
| 颜色 | `e32a00` | 暗红，拼成 `\|cffe32a00…\|r` |
| 透明度 | `1` | `SetTextTagColor(…,255)` |
| 存活 | `1` 秒 | `SetTextTagPermanent(false)` + 定时 `DestroyTextTag` |
| 位置 | 单位 XY，Z 偏移 `50` | `SetTextTagPos(x - StringLength*size*0.5, y, 50)` |
| 速度 | `(0, 0.05)` | 向上飘（`SetTextTagVelocity` 的 y 分量） |

> 这一支**不看暴击**，玩家单位挨打永远是一行红字；也不受“伤害数字”开关影响。

### B. 怪物/BOSS：逐位「数字模型」

```lua
local function show_damange_number(x, y, z, damage, modelTable, scale, targetUnit, damagePlayer)
    -- 同一单位 1 秒内的第 N 次出伤：整体上移 20*N
    local n = hcache.get(targetUnit, "damage_number", 0)
    z = z + n * 20
    hcache.set(targetUnit, "damage_number", n + 1)
    htime.setTimeout(1, ... n-1 ...)

    local s = tostring(math.floor(damage))
    for i = #s, 1, -1 do                      -- 从末位开始“从右往左”摆
        local model = modelTable[s:sub(i,i)]
        if 开关打开 and damagePlayer ~= 本地玩家 then model = "" end
        heffect.xyz(model, x + (i-1)*47*scale, y, z, 0, 1, scale, scale, scale)
    end
end
```

调用点：`show_damange_number(x, y, z + 20, damage, model, scale, 被打单位, 来源玩家)`
其中 `z = hunit.h(u) + 130`（`h = 地形高度 + 飞行高度`）。

#### 位置/尺寸公式

| 项 | 公式 | 备注 |
|---|---|---|
| 锚点 X | `GetUnitX(target)` | 数字从单位中心开始向右排 |
| 锚点 Y | `GetUnitY(target)` | |
| 锚点 Z | `h + 130 + 20 + 20*叠层数` | `h` = 地形高 + 飞行高 |
| 字距 | `47 * scale` | 普通 18.8，暴击 32.9 |
| 缩放 | `scale = 0.4`（普通）/ `0.7`（暴击） | `EXEffectMatScale` 三轴同值 |
| 朝向 | 无旋转参数 | 模型本身是面向 ±X 的方形面片 |

#### 模型表（`eventReaction.lua:16-62`）

| 类型 | 普通 | 暴击 |
|---|---|---|
| 物理 | `war3mapImported\1wlshanghai0-9.mdx` | `war3mapImported\Bshanghaibaoji0-9.mdx` |
| 法术 | `war3mapImported\fsshanghai0-9.mdx` | `war3mapImported\fsshanghaibaoji0-9.mdx` |

| 模型 | 序列 | 图集 |
|---|---|---|
| `1wlshanghai*` | `Birth AZ` 0.000–0.700s | `war3mapImported\az_tex_00003.blp` |
| `fsshanghai*` | `Birth AZ` 0.000–0.700s | `war3mapImported\az_tex_00002.blp` |

→ 暴击数字模型只有 `Death` 一段，所以“创建即销毁”时播的就是那段 1.3 秒的暴击动画；

## 4. 数字本身是怎么算出来的

`scripts/damaging.lua` 用 `damaging.defined(key, fn)` 按**定义顺序**串成流水线（`foundation/array.lua` 保证插入序），
`lib/skill.lua:720` 用 `damaging.actions.forEach` 依次跑，`damage <= 0` 提前终止：

| # | key | 作用 | 公式/效果 |
|---|---|---|---|
| 1 | `invincible` | 无敌 | `damage = 0` |
| 2 | `dengjiyazhi` | 等级差 | `levelGap = clamp(srcLv - tgtLv, -10, 10)` |
| 3 | `shanbi` | 闪避 | `hit - shanbi + levelGap` 与 `random(0,10000)/100` 比；命中则 `damage=0` + `AZ_hero_miss2.mdx` |
| 4 | `zhaojia` | 招架 | 仅物理/普攻；`hit - zhaojia + levelGap`；成功 `damage=0` + `AZ_zhaojia.mdx` + 音效 |
| 5 | `gedang` | 格挡 | `damage *= 1 - 0.01*gedang_jianshang` + `AZ_gedang.mdx` |
| 6 | `defend` | 护甲/魔抗/穿透 | 物理：`*(1 - 3*armor/(1000+3*armor))`；法术：`*(1 - 3*mojia/(1000+3*mojia)) * (1 - mokang/100)` |
| 7 | `multiplier` | 全局增伤 | `*(100+quanju)/100 * 系别增伤 * (100+jinu)/100` |
| 8 | `jianshang` | 减伤 | `*(100 - jianshang)/100` |
| 9 | `critical` | 暴击 | 概率 `wu_bao/fa_bao + levelGap`；命中 `damage *= wu_baoshang/fa_baoshang%`，`isCritical = true` |
| 10 | `customSource` | 职业/普攻增伤 | 触发 `damagingCustomSource/Target`；普攻 `*(1 + pugong_shanghai/100)` |
| 11 | `element` | 五行/光暗增伤 | 每个元素 `*(1+enhance/100) * (1+yishang/100)` |
| 12 | `tuanduijuese` | 团队角色 | 进攻手/先锋 ×1.02，守护者 ×0.1（自身）/×0.4（目标） |
| 13 | `JJC` | 竞技场 | 目标带“竞技场”buff 且来源是玩家 → ×0.05 |
| 14 | `final_damage_reduction` | 最终减伤 | `max(damage - X, 1)` |
| 15 | `killing` | 致死检查 | `damage >= 当前血` → 触发 `dying` |

之后：护盾吸收 → 扣血 → `beDamage`。
**所以屏幕上飘的数字 = 走完全部减伤/暴击/护盾后的“实际掉血值”**（不是面板攻击力）。

## 6. 复刻要点

```lua
-- ① 文本版（最省事，人人可见、不看暴击）
local tag = htextTag.create2XY(x, y, "-" .. string.format("%.0f", dmg), 9, "e32a00", 1, 1, 50)
htextTag.setVelocity(tag, 0, 0.05)

-- ② 模型数字版（WoW 风格，需 4 套 0-9 模型）
local scale = crit and 0.7 or 0.4
local tbl   = crit and BAOJI_MODELS or NORMAL_MODELS
local s     = tostring(math.floor(dmg))
for i = 1, #s do
    heffect.xyz(tbl[s:sub(i,i)], x + (i-1)*47*scale, y, h + 150, 3, 1, scale, scale, scale)
end
```

对应 JASS（不用 h-lua）：

```jass
function ShowDamageText takes unit u, real dmg returns nothing
    local texttag t = CreateTextTag()
    call SetTextTagText(t, "-" + I2S(R2I(dmg)), 9 * 0.023 / 10)
    call SetTextTagColor(t, 227, 42, 0, 255)
    call SetTextTagPos(t, GetUnitX(u), GetUnitY(u), 50.)
    call SetTextTagPermanent(t, false)
    call SetTextTagVelocity(t, 0., 0.05)
    call SetTextTagLifespan(t, 1.)
    call SetTextTagFadepoint(t, 0.7)
endfunction
```

复刻/移植时注意：

1. **TextTag 上限**：引擎 100 个；h-lua 自己限 `htextTag.limit = 90`，超了 `create` 返回 `nil`
   （`create2XY` 直接 `SetTextTagPos(nil, …)`，实际会报错/无效，自己写要判空）。
2. **一次性特效**：`duration = 0` 依赖“创建→销毁”这一下把模型动画带出来；
   要稳就用 `duration > 0` 或 `hmodelTag.word` 的“`-1` 创建 + 定时器逐帧改 Z + 结束时销毁”。
3. **叠层**：同一目标 1 秒内的多次伤害要用 `damage_number` 计数器把后到的数字抬高 20，
   否则多段伤害会糊在一起。
4. **逐位顺序**：`for i = #s, 1, -1` 只是“从右往左生成”，坐标用的是 `(i-1)*字距`，
   最终仍是正常从左到右（首位在 x 处）。
5. **神圣伤害**：作者自己留了 TODO，目前借用法术模型，没有独立第三套数字。

## 8. 为什么 `EXSetEventDamage(0)`，伤害又是怎么“补”回来的

### 8.1 时序

```
引擎算出本次伤害
  ↓ 触发 EVENT_UNIT_DAMAGED（注册成 Condition，lib/eventBinder.lua:666）
    local damage = GetEventDamage()      -- 先读原值
    EXSetEventDamage(0)                  -- 再清零（:671）
    htime.setTimeout(0, function() ... end)   -- 推迟到下一个计时器周期
  ↓ 事件返回，引擎按“0”结算：不掉血、不判死、不触发原生后续
  ↓ 下一个计时器周期：
    hskill.damage{ damage = damage, damageSrc = attack, damageType = WULI }
      ① 15 步伤害流水线（scripts/damaging.lua）
      ② 护盾吸收 hbuff.xiaochuhudun（lib/buff.lua:413）
      ③ hunit.subCurLife → SetUnitState(LIFE, 当前血 - 伤害)（lib/unit.lua:401/418）
      ④ 血 ≤ 0 → 引擎走正常死亡 → lib/eventBinder.lua 的 dead 分支
```

### 8.2 为什么要清零

1. **防双倍**：引擎在事件返回后会把 `GetEventDamage()` 的值扣到血上；如果不清零，就是“引擎扣一次 + 脚本再扣一次”。
2. **换掉引擎规则**：这张图要跑自己的护甲公式 `1 - 3*armor/(1000+3*armor)`、闪避/招架/格挡、暴击倍率、护盾、五行增伤、竞技场修正……引擎那套（护甲减伤、伤害类型、法球、吸血、反弹）必须先关掉，否则两套规则叠加。
3. **数字对得上**：屏幕上的“出伤”直接取 `options.damage`，清零后只有脚本算出的那一份，飘字 = 真实掉血。
4. **顺序**：必须先 `GetEventDamage()` 读出来，再 `EXSetEventDamage(0)`；反过来就取不到原值了。

### 8.3 为什么用 0 秒计时器，而不是当场扣

- `EVENT_UNIT_DAMAGED` 是“**即将**造成伤害”的通知，引擎在事件返回后还有自己的结算与死亡判定；在事件里直接改血容易被覆盖，或让引擎的死亡流程作用在“已改过的血”上。
- `hskill.damage` 内部会触发 `damage / beDamage / attack / beAttack / dying` 等一堆事件，这些事件里还可能再造成伤害（反伤、连击、DOT）；必须离开引擎的伤害调用栈，避免递归与重入。
- 死亡/尸体清理（非英雄 3 秒后删除）也不适合在伤害事件里做。

### 8.4 怎么“补”回来

```lua
-- lib/unit.lua:418
function hunit.subCurLife(u, val)
    hunit.setCurLife(u, hunit.getCurLife(u) - val)   -- :401
end
-- setCurLife → cj.SetUnitState(u, UNIT_STATE_LIFE, ...)
```

- **不是** `UnitDamageTarget`：那会再次触发同一个 `EVENT_UNIT_DAMAGED`（又被清零、又排一个 0 秒结算），造成递归/翻倍。
- 直接写生命值 = 绕过整个引擎伤害系统，所以“补伤害”本质是**手写扣血**。
- 扣血前先过护盾：`hbuff.xiaochuhudun` 遍历 buff 的 `hudunzhi`，扣完把护盾 buff 删掉，返回剩余伤害。
- 血 ≤ 0 后由引擎正常死亡；`dead` 分支里补上 `UNIT_DEAD` 标记、`dead/kill` 事件、击杀数与非英雄清理。

### 8.5 这套写法的代价（都在代码里能验证）

| 现象 | 原因 |
|---|---|
| 引擎吸血/荆棘/伤害反弹/法球全失效 | 原生伤害恒为 0，引擎侧从不“造成伤害” |
| 普攻伤害值来自 `attack` 属性，不是 `GetEventDamage()` | `lib/skill.lua:712` 用 `hattribute.getWithLimit(source,"attack",0)` 覆盖 |
| 所有原生伤害都被当普攻 | `isAttack = IsEventAttackDamage() or true` 恒真 |
| 小于 0.125 的伤害、目标已死/已销毁时整段丢伤害 | `hskill.damage` 开头直接 `return`，而原生已被清零 |
| 击杀归属要自己记 | `hevent.setLastDamage` + `hplayer.addKill`，引擎不知道凶手 |
| 同帧多次伤害的实际结算晚一个计时器周期 | `setTimeout(0, ...)`；致死靠流水线里的 `killing` 预触发 `dying` |

### 8.6 不想全盘接管时

- 1.31+ 官方有 `BlizzardSetEventDamage` / `SetEventDamage`，可以只做“数值修正”（比如 `SetEventDamage(damage * 0.5)`），其余交给引擎；
- 只有像这张图一样要自定义整套伤害规则时，才需要“清零 + 自己 `SetUnitState` 扣血”。
