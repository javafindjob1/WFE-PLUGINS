War3DeathSettlement 发布包
==========================

版本：2.2.24
构建形式：单个 .NET 10 自包含 x64 桌面程序，WFE 使用单个 ddh.dll。

运行前置条件：
  - Microsoft Edge WebView2 Runtime

一、包内内容
------------
Desktop\War3DeathSettlement.exe
  桌面结算程序，已内嵌死亡结算、伤害事件和战场单位页面。
Game\WFE-Libraries\ddh.dll
  WFE 加载的单一伤害采集模块，只负责伤害钩子和 SQLite 落库。

二、游戏内行为
--------------
- 游戏内不显示任何结算按钮。
- 游戏内不显示结算页、覆盖层、阵亡总结或承伤图表。
- 不启动 ddh_web，不创建游戏内画面共享内存。
- ddh 协议升级为 v39，事件内保存受害者和来源单位的战斗属性快照，总长 149568 字节。
- 本版已完全删除共享内存和桌面注入：ddh 使用进程内事件环，桌面只读 SQLite。
- 本版删除全部 CUnit 属性请求、属性结构、native/SLK/EX 属性探测和桌面内存扫描；
  战场单位缺省属性显示 `?`。
- 伤害回调内不再调用名称注册表、技能列表解析或其他 game.dll 函数；名称、蝗虫
  判定和单位缓存更新改为 Hook 退出后延迟处理。
- 自动伤害采集路径进一步删除名称注册表、技能列表和联盟 JASS 调用，只保留
  纯内存读取；新事件名称回退为类型码。
- 第一步恢复单位名称：伤害入口从 CUnit 类型码读取并缓存，称谓和镜像后续分步恢复。
- 第二步恢复称谓：伤害入口从 CUnit+0x1F0 类型数据读取并按类型码缓存。
- 名称和称谓只在读取成功后缓存；无效指针、访问异常或读取失败不会写入缓存。
- 战场单位恢复最小/最大攻击力、攻击范围、护甲、攻击速度、攻击间隔和蝗虫；
  攻击频率由界面计算。
- 恢复游戏内原生阵亡总结：四类伤害占比、来源分段、10 秒承伤柱状图和总计；
  面板仅在 Hook 退出后由本机游戏线程创建，不使用公共聊天、共享内存或 WebHost。
- 阵亡总结新增缩版：默认显示标题、总伤害和伤害类型条；点击右侧箭头可展开/收起。
- 每次英雄阵亡均重新从缩版开始显示。
- 单位死亡数据仍写入 SQLite，可在桌面程序里查看。

三、安装游戏内采集
------------------
1. 完全退出魔兽争霸和 WFE。
2. 双击 install_release.cmd；如果系统阻止，请右键以管理员身份运行。
3. 安装器会更新：
   C:\3rd\wc3gamesearcher\WFE\Application\Libraries\ddh.dll
4. 安装器会删除旧版 C:\launch\ddh_web、页面资源和游戏内启动脚本。
5. 重新启动 WFE，再启动魔兽并进入地图。

四、桌面版
----------
直接运行 Desktop\War3DeathSettlement.exe。
桌面版是 .NET 10 自包含单文件程序，无需另装 .NET；历史、日志和设置路径仍按程序配置
写入用户目录。

桌面程序不注入游戏：
1. 采集必须由 WFE 加载 Game\WFE-Libraries\ddh.dll。
2. 桌面程序只读取 ddh 写入的 SQLite。
3. 找不到 WFE 采集数据时，桌面程序显示等待状态。

五、当前界面要点
----------------
- 三个页签：死亡结算、伤害事件、战场单位。
- 每页结算 200 条，每页伤害事件 500 条。
- 伤害事件固定前三列：时间、触发单位、伤害来源。
- 筛选、分页、历史会话和诊断都只在桌面程序中操作。
- “地图伤害 > 0、净掉血 = 0”是允许的：伤害可能被同帧回血抵消。

六、校验
--------
SHA256SUMS.txt 包含包内所有文件的 SHA-256。
发布包不得包含 Game\ddh_web、dss.html、dss-assets 或 ddh_web_launcher。
